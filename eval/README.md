# Воспроизведение проверок

Рабочий каталог — корень репозитория. Нужны Python 3.12 и Node.js 24.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
.\.venv\Scripts\python.exe scripts/generate_chat_data.py
.\.venv\Scripts\python.exe scripts/benchmark_chat.py --catalog db/ktru_catalog.jsonl.gz --output reports/benchmark.json
cd backend
..\.venv\Scripts\python.exe -m pytest -q tests
..\.venv\Scripts\ruff.exe check --line-length 100 . ../scripts
..\.venv\Scripts\ruff.exe format --check --line-length 100 . ../scripts
cd ../frontend
npm ci
node --test tests/api.test.mjs
npm run lint
npm run build
```

На Linux используйте `.venv/bin/python` и `.venv/bin/ruff` вместо Windows-путей.

`positions_1000.jsonl` содержит ровно 1000 валидных объектов `parser.Item`:
`row_number`, `text`, `columns`. CSV описывает те же строки для загрузки через API.
100 строк имеют длину 2000 символов, 100 содержат специальные символы,
100 содержат текст, похожий на инструкцию для модели. Все данные синтетические.
Некорректные случаи хранятся отдельно в `negative.json` и проверяются тестами.
Повторная генерация даёт одинаковое содержимое файлов.

Замеры всегда используют имитатор GigaChat и словесный поиск без Ollama.
Модель, промпт и лимит параллельных запросов приложения сохраняются;
провайдер заменяется только в процессе тестового скрипта.
Скрипт не читает `.env`, не вызывает внешние сервисы и не требует API-ключа.
Если `--catalog` не указан, используется маленький синтетический каталог.
`--backend-root` позволяет измерить другую копию backend тем же скриптом.

Режим A: 20 последовательных обращений по одной строке;
B: все 1000 строк, 100 пакетов по 10, два потока и существующий семафор провайдера;
C: по 200 строк при 1, 2, 4 и 8 потоках, по 10 строк на запрос.
Отдельно HTTP API проходит загрузку → очередь → обработку → CSV-выгрузку:
пять последовательных заданий, одно задание из 1000 строк и
1/2/4/8 одновременных заданий по 10 строк.
Число `requests` в разделе `api_jobs` обозначает завершённые задания,
в `extraction` — вызовы извлечения пакетами. Опрос прогресса входит во время задания.

p95 выводится начиная с 20 наблюдений, p99 — со 100; это описательные
оценки малой выборки, а не достоверный прогноз хвостов задержки.
CPU — время процесса и доля одного ядра; память — накопленный максимум
рабочего набора процесса, включая загрузку каталога и предыдущие режимы.
`synthetic_service_seconds` — время имитатора с заданной задержкой 5 мс,
а не время генерации ответа нейросетью. Генерация данных и загрузка каталога
измеряются отдельно. Реальная точность модели, стоимость, ограничения
провайдера и скорость Ollama этими замерами не проверяются.
