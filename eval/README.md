# Наборы для проверок

Ключи и внешние сервисы не нужны. `positions_1000` и `negative.json` — синтетика,
`real_12` и `cards_1000` — эталоны с кодами КТРУ для `scripts/evaluate.py`.

- `positions_1000.jsonl` — ровно 1000 объектов `parser.Item` (`row_number`, `text`, `columns`);
  `positions_1000.csv` — те же строки для загрузки через интерфейс или API.
  Восемь товаров по кругу (бумага, лампа, ноутбук, кабель, кефир, стул, ручка, фильтр);
  100 строк длиной 2000 символов, 100 со спецсимволами и формулами, 100 с текстом,
  похожим на инструкцию для модели. Набор для нагрузки и устойчивости, кодов КТРУ в нём нет.
- `negative.json` — некорректные загрузки (пустой файл, чужая сигнатура, exe), проверяются тестами.

Повторная генерация даёт те же файлы:

```bash
python scripts/generate_chat_data.py
```

Точность кодов на `positions_1000` считается по категории: код верный, если наименование
выбранного кода КТРУ начинается с допустимого названия товара («Бумага для офисной техники»,
«Кефир»…). «Фильтр 10 мм» слишком общий и не размечен. Точный код проверяется
на черновом эталоне (291 строка, `../b2b/tests/acceptance/gold/draft_ai.jsonl`).

## Эталоны с кодами КТРУ

Пары «файл для загрузки + ответы» в формате `scripts/evaluate.py`: в `.csv` — шапка
«Наименование;Характеристики» и строки, в `.jsonl` — `{"row_number", "ktru_code"}`
(`row_number` — строка файла, шапка — строка 1). Все коды проверены по дампу каталога:
есть и действуют (`ACTIVE`) на 20.10.2026.

| Набор | Строк | Откуда | Чем полезен и чем ограничен |
|---|---|---|---|
| `real_12` | 12 | образец спецификации с кодами человека (`produkty_1.xlsx` из чата команды) | реальные формулировки; мало строк, 11 разных кодов, почти всё — молочка и мясо. В коде курицы в исходнике был лишний пробел (`10.12.10.000- 00000005`), в эталоне убран |
| `cards_1000` | 1000 | «Спецификация_1000_с_КТРУ» из чата команды | 1000 разных кодов, 37 разделов ОКПД2 (электроника 26.xx — 32 %), шаблонов групп нет. **Лёгкий набор:** наименование в каждой строке дословно равно названию карточки, характеристики скопированы из карточки — точность на реальных закупках будет ниже |

```bash
docker compose run --rm -T --no-deps -v "$PWD/eval:/eval:ro" -v "$PWD/scripts:/scripts:ro" \
  backend python /scripts/evaluate.py /eval/cards_1000.csv /eval/cards_1000.jsonl --api http://backend:8000
```
