# Наборы для проверок

Все данные синтетические, ключи и внешние сервисы не нужны.

- `positions_1000.jsonl` — ровно 1000 объектов `parser.Item` (`row_number`, `text`, `columns`);
  `positions_1000.csv` — те же строки для загрузки через интерфейс или API.
  Восемь товаров по кругу (бумага, лампа, ноутбук, кабель, кефир, стул, ручка, фильтр);
  100 строк длиной 2000 символов, 100 со спецсимволами и формулами, 100 с текстом,
  похожим на инструкцию для модели. Набор для нагрузки и устойчивости, кодов КТРУ в нём нет.
- `negative.json` — некорректные загрузки (пустой файл, чужая сигнатура, exe), проверяются тестами.

Повторная генерация даёт те же файлы:

```bash
python scripts/generate_chat_data.py
```

Точность кодов на `positions_1000` считается по категории: код верный, если наименование
выбранного кода КТРУ начинается с допустимого названия товара («Бумага для офисной техники»,
«Кефир»…). «Фильтр 10 мм» слишком общий и не размечен. Точный код проверяется
на черновом эталоне (291 строка, `../b2b/tests/acceptance/gold/draft_ai.jsonl`).
