# Баги и ограничения — 29.10.2026

Это все известные по текущей проверке проблемы, а не гарантия отсутствия других. Разделены ошибки, недостатки проверки и ограничения поставки.

## Открытые подтверждённые ошибки

### B01 — название смешивается с атрибутами (высокий приоритет)
Пример: «Ноутбук Lenovo ThinkPad T14, оперативная память 16 ГБ…» возвращает name «Ноутбук Lenovo ThinkPad T14», хотя brand/model выделены отдельно и промпт требует чистое название. На 75 development-строках строгий name 14/75 в первом запуске, 34/75 в повторном. Файл backend/extractor.py. Есть кандидат product_name, но его результат ещё не подтверждён. Проверить dev/holdout, сохранение назначения товара, составные названия и регрессию классификации. Не удалять полезные части названия ради процента.

### B02 — повторный замер кандидата использовал старый модуль (высокий)
В scripts/evaluate_attributes.py путь /app вставлен первым. Кандидат был скопирован в /tmp/extractor.py, но импортирован /app/extractor.py. Поэтому attributes-candidate.json переименован локально в attributes-repeat-old-runtime.json. Исправить способ изолированного запуска, записывать путь/хеш модуля. Не выдавать 34/75 за эффект изменения.

### B03 — полный scripts/bench.py ссылается на отсутствующий primer-эталон (средний)
В SETS есть primer -> dataset/primer/primer_reference.jsonl, а файл удалён в рабочем дереве. Запуск всех наборов по умолчанию может завершиться ошибкой на этом шаге. Выяснить намеренность удаления; восстановить проверенный эталон либо явно убрать недоступный набор из default, документировать причину. Не молча игнорировать неудачную проверку.

### B04 — README API-сценарий не учитывает согласия (средний)
Для нового аккаунта описанных login/upload недостаточно. Нужны актуальная версия /api/legal, согласие регистрации и files. Иначе пользователь получает 400/403 при следовании инструкции. Добавить готовую последовательность с cookie и проверить её на новом аккаунте.

## Недостатки тестов и неподтверждённые риски
- Старый тест атрибутов — 12 простых явно подписанных строк; не доказывает >=90% на разнообразном вводе. Новый набор составлен ассистентом и нуждается в независимом ревью; holdout 25 ещё не использован.
- backend/acceptance.py проверяет ручную правку тем же кодом. Нужно заменить на другой допустимый и подтвердить сохранение.
- Экспорт в приёмке проверяется по HTTP 200 и непустому телу. Нужна проверка строк и изменённых значений CSV/XLSX.
- PDF >50 страниц проверен только на повторяющейся искусственной строке. Реальные многострочные таблицы и переносы страниц не подтверждены. OCR сканов отсутствует; это явное ограничение, а не доказанный дефект текстового PDF.
- Правка product_name может чрезмерно обрезать составные названия по совпадению бренда/модели или значения характеристики. Требуются отрицательные тесты и регрессия; пока это риск кандидата, не установленная ошибка рабочих данных.
- У ручных и запомненных человеческих решений нет выдуманного процента модели. Это семантически честно, но буквальное требование «для каждого товара» нужно пояснить на защите или показывать исходную оценку отдельно.
- 192,612 с / 99% — прежний замер, не финальный после всех изменений. Другие квоты ключей/железо могут изменить время.
- Полные подробные журналы находятся в Docker logs, не в PostgreSQL; в БД есть ошибки и этапы заданий, но нет полного аудита всех действий.

## Ограничения поставки, не ошибки алгоритма
- Два файла каталога вне Git: чистого clone недостаточно. Архив и SHA256 ещё не подготовлены.
- Свежая установка после миграций 0003/0004 на другом ПК не подтверждена.
- Много изменений ещё не зафиксировано в сдаваемой ветке. Видео <=5 минут не подготовлено; реквизиты команды не получены.
- Часовой пояс дедлайна, канал сдачи и доступ жюри к API эмбеддингов неизвестны.
- Для публичного сайта ещё нужны проверенные реквизиты оператора и HTTPS. Политика — рабочий текст, не юридическое заключение.
