# Кто что правит

Каждый правит только файлы своей зоны. Нужна правка в чужой зоне — пишешь владельцу (issue или
сообщение в чат команды), он делает сам или разрешает явно. Как всё устроено — в
[README.md](README.md), раздел 4–6.

## Роли

- **Кирилл — тимлид и архитектор.** Устройство системы, общие контракты (раздел «Контракты»
  ниже), docker-compose, правила и документация. Ревьюит изменения контрактов у всех.
  Свои изменения вливает в `main` сам.
- **Егор, Женя, Лёша** — владельцы своих зон: пишут код, вливают изменения после зелёных проверок
  и ревью.
- **Артас — тестировщик.** Пишет тесты, ведёт эталон и замеры, проверяет руками, заводит найденные
  ошибки владельцу зоны. Код зон не правит — ошибку чинит владелец.

## Контракты между зонами

Это данные, которые одна зона отдаёт другой. Меняет их только владелец зоны-источника и только
после ревью Кирилла; все, кто их читает, обновляют свой код в том же изменении.

| Контракт | Источник → кто читает | Где описан |
|---|---|---|
| `parser.Item(row_number, text, columns)` | Кирилл → Женя | `backend/parser.py` |
| атрибуты `{name, brand, model, characteristics, search_text, measure, source, fallback}` | Кирилл → Женя, Лёша | `backend/extractor.py`, тип `Item.attributes` в `api.ts` |
| кандидат `{code, name, okpd2_code, status, score, cosine, shared_words, matched_characteristics, numeric_matches, characteristics}` | Кирилл → Егор, Женя, Лёша | `Catalog._rank` в `search.py`, тип `Candidate` в `api.ts` |
| вердикт `{confidence, zone, needs_review, status, summary}` | Егор → Женя | `confidence.assess` |
| JSON API (задание, позиция, ошибки) | Женя → Лёша | `api.py`, `api.ts`, Swagger `/api/docs` |
| статусы позиции `auto / needs_review / corrected / accepted / failed` | Женя → все | `ITEM_STATUSES` в `api.py` |

## Общие правила

1. **Проверки перед каждым изменением** — все зелёные:
   ```bash
   cd backend && python -m pytest -q tests && ruff check --line-length 100 . && ruff format --check --line-length 100 .
   cd frontend && npm run lint && npm run build
   ```
2. **Изменение точности — только с замером.** Любая правка промпта, весов, порогов или
   правил поиска прикладывает цифры «было → стало» на реальных файлах **и** на черновом эталоне.
   Улучшилось на одном и ухудшилось на другом — не вливаем.
3. **Секреты** — только в `.env`; в коммитах, логах и скриншотах ключей нет.
4. **Код и комментарии — на английском, тексты для пользователя — на русском**
   (во фронте — только в `texts.ts`). Сообщения коммитов — на английском.
5. **Python:** 3.12, версии зависимостей через `==`, ruff со строкой 100, функции короткие,
   файл — до ~300 строк.
6. **Frontend:** одна UI-библиотека (antd), цвета только переменными из `theme.css`, иконки —
   lucide-react, всё доступно с клавиатуры.
7. **Не править:** `db/ktru_catalog.jsonl.gz` (его меняют только целиком, новой выгрузкой),
   `package-lock.json` руками (только через `npm install`).
8. **Безопасность не ослаблять:** лимиты загрузки, проверку сигнатуры, проверку значений
   нейросети по строке, экранирование выгрузки. Убрать или ослабить — только через Кирилла.

## Как новая функция проходит через зоны (пример: колонка «Ед. изм.»)

1. **Кирилл** — `parser.py` находит колонку единиц; `search.py` сравнивает её с `units` кода
   и даёт бонус; контракт кандидата получает поле `unit_match`.
2. **Егор** — проверяет, нужно ли учитывать совпадение единиц в уверенности, приносит замер.
3. **Женя** — колонка единиц попадает в выгрузку, если нужно.
4. **Лёша** — показывает совпадение единиц в панели позиции.
5. **Артас** — тест на файл с колонкой «Ед. изм.», замер «было → стало», ручная проверка.

## Сценарий ручной приёмки (Артас, перед каждой сдачей)

1. `docker compose up --build` с нуля — все 4 сервиса `healthy`/`Up`, в шапке
   «Каталог: 81 509 кодов».
2. Загрузить `spec_50.csv` → прогресс → результаты; плитки фильтруют таблицу.
3. Открыть позицию → выбрать другой код → «Принять» → Esc закрывает панель.
4. «Исправить» → поменять характеристику → «Сохранить и подобрать код» → код и пояснение
   обновились; пустое наименование не сохраняется.
5. Ссылка кода открывает zakupki.gov.ru в новой вкладке.
6. Выгрузка xlsx и csv: исходные колонки, атрибуты, код, уверенность, статус; значения
   с `=` в начале — с апострофом.
7. Обе темы на 1440 и 768 px: ничего не обрезано, текст читается.
8. Клавиатура: Tab, стрелки по таблице, Enter, Esc, выгрузка с клавиатуры.
9. Замер `spec_1000.xlsx` — быстрее 5 минут; замер точности на реальных файлах — записать цифры.
