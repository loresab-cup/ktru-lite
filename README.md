# КТРУ-классификатор (lite)

Кейс-чемпионат B2B-РТС, задача 5. Загружаете спецификацию (xlsx, csv, docx, pdf, txt) — система
извлекает из каждой строки наименование, бренд, модель и характеристики, подбирает код КТРУ
с уверенностью в процентах, вы проверяете спорные позиции и выгружаете результат в xlsx или csv.

## Запуск

Нужны Docker и дамп каталога `db/ktru_catalog.jsonl.gz` (в git не хранится).

```bash
cp .env.example .env        # вписать LLM_API_URL (без /v1) и LLM_API_KEY
docker compose up --build
```

Интерфейс — http://localhost:3000, API — http://localhost:8000/api/docs.
Первая сборка скачивает модель bge-m3 (~1,2 ГБ); первый старт backend читает дамп в матрицу
(~20 с) и кладёт её в кэш на томе, следующие старты занимают секунды.
Без ключа нейросети всё работает: атрибуты извлекаются правилами.

## Как устроено

```
браузер ──► nginx (frontend :3000) ──/api──► FastAPI (backend :8000) ──► PostgreSQL (jobs, items)
                                                │
                    POST /api/jobs ─► файл под uuid ─► jobs.status = queued
                                                │
               2 потока-воркера: SELECT … FOR UPDATE SKIP LOCKED, пакеты по 100 позиций
                                                │
   parser.py ─► extractor.py ──────────► embedder.py ──────► search.py ────────► confidence.py
   файл→строки  нейросеть по API         bge-m3 в Ollama     каталог в памяти:   логистическая
                (или правила), проверка  текст = search_text  точный косинус     функция от топ-1
                значений по строке       + исходная строка    + бонус за слова   и отрыва, зоны
```

- **parser.py** — все листы xlsx, csv в utf-8/cp1251 с `;` `,` или табуляцией, таблицы
  и абзацы docx, текст pdf (≤ 200 страниц), txt по строкам. Шапка ищется по словам
  «наименование», «товар», «характеристики», «кол-во»; итоги и повторы шапки пропускаются.
- **extractor.py** — пакеты по 10 строк, 16 запросов параллельно, бюджет 150 с на задание.
  Строки передаются как JSON-данные; значение принимается, только если оно есть в строке.
- **search.py** — матрица 81 509 × 1024 в памяти, точный косинус (HNSW терял до 14 % верных
  кодов), 50 ближайших, `score = cosine + 0.02 × общие слова` (наименование + значения
  характеристик), топ-5. Без Ollama — поиск по словам.
- **confidence.py** — уверенность %, зоны high ≥ 85 (авто), medium 60–85, low < 60;
  отменённый код никогда не уходит в авто; пояснение — какие слова и характеристики совпали.
- **api.py** — очередь на таблице `jobs`, эндпоинты под `/api`, выгрузка с защитой от
  формульных инъекций.

## Переменные `.env`

| Переменная | Значение |
|---|---|
| `LLM_API_URL` | адрес API по протоколу Anthropic, без `/v1` |
| `LLM_API_KEY` | ключ; пусто — атрибуты извлекаются правилами |
| `LLM_API_MODEL` | модель, по умолчанию `claude-sonnet-5` |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | учётные данные PostgreSQL в compose |

## Разработка

```bash
cd backend
pip install -r requirements.txt pytest==9.1.1 ruff==0.17.1
python -m pytest -q tests
ruff check --line-length 100 . && ruff format --check --line-length 100 .
```

Тесты парсера читают файлы-примеры из `../b2b/backend/tests/fixtures` (путь меняется
переменной `B2B_FIXTURES`); без них эти тесты пропускаются.

```bash
cd frontend
npm ci
npm run dev      # http://localhost:5173, /api проксируется в backend на :8000
npm run lint && npm run build
```
