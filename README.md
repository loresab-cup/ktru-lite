# КТРУ-классификатор (lite)

Кейс-чемпионат B2B-РТС, задача 5. Пользователь загружает спецификацию закупки (xlsx, csv, docx,
pdf, txt). Система достаёт из каждой строки наименование, бренд, модель и характеристики,
подбирает код КТРУ с уверенностью в процентах, человек проверяет спорные позиции, при
необходимости исправляет код или атрибуты и выгружает результат в xlsx или csv.

Кто какие файлы правит — в [OWNERSHIP.md](OWNERSHIP.md).

**Коротко о текущей версии:** 1000 позиций за 1,5–3 минуты, все строки обрабатывают нейросети
(несколько сразу), эмбеддинги на видеокарте, готовые строки видны в таблице во время обработки,
обработку можно остановить, спорные коды перепроверяет нейросеть по пяти кандидатам поиска.
Запуск — одна команда `docker compose up -d --build`.

### Критерии приёмки (задача 5) и как они выполнены

| № | Критерий | Метрика | Результат | Как проверить |
| --- | --- | --- | --- | --- |
| 1 | Извлечение атрибутов | ≥ 90 % (наименование, бренд, модель) | **96,8 %** при сравнении наименования «одно содержит другое» (наименование 99,7 %, бренд 97,9 %, модель 92,8 %); при точном совпадении текста наименования — 81,2 % | черновой эталон, 291 строка |
| 2 | Точность классификации | ≥ 85 % на тестовом датасете | **реальная спецификация с кодами человека: 11–12 из 12** (разные прогоны); черновой эталон: **88,1 %** на строках, где верный код — не шаблон группы (как выбирают люди), 73,5 % на всех; верный код в топ-5 — 96,9 % | `scripts/evaluate.py` |
| 3 | Массовая обработка | 1000 позиций < 5 мин | **185 с**, все строки через нейросети; потолок задания `JOB_TIME_LIMIT` 270 с | positions_1000 |
| 4 | Вывод уверенности | % для каждого товара | колонка «Уверенность» (число, полоска, зона), пояснение в панели; калибровка: средняя уверенность 88,7 % = доля верных кодов 88,7 % | раздел 6.4 |
| 5 | Ручная корректировка | исправить код в интерфейсе | панель позиции: выбор из топ-5, поиск по каталогу, ввод кода вручную, правка атрибутов с повторным подбором, «Принять» | раздел 3 |
| 6 | Асинхронность | очередь задач | таблица `jobs` + воркеры (`FOR UPDATE SKIP LOCKED`), пул нейросетей, потоковый вывод, отмена | раздел 6.5 |
| 7 | Архитектура | `docker-compose up --build` | одна команда (`docker-compose` и `docker compose`), GPU подключается из `.env` | раздел 1 |

Про 73,5 % на всём черновом эталоне: его коды выбраны генератором **случайно**, в том числе
«шаблоны групп» (19 % строк при 9,8 % шаблонов в каталоге). Шаблон и обычный код одной группы
часто совпадают по наименованию и данным, различить их невозможно; поиск сознательно предпочитает
обычный код — так выбирает человек (в реальной спецификации 0 шаблонов из 12) и это подняло
реальный файл с 9 до 12 из 12. 49 из 77 расхождений с черновиком — ровно эти случаи.

Проверка на своём размеченном файле (сервис запущен):

```bash
python scripts/evaluate.py spec.xlsx reference.jsonl
```

`reference.jsonl` — по строке на позицию: `{"row_number": 2, "ktru_code": "...", "name": "...",
"brand": "...", "model": "..."}`; скрипт печатает точный код, топ-5, долю верных «авто» и атрибуты.

## 1. Быстрый старт

### Что нужно

- **Docker Desktop** (Windows/macOS, на Windows — с WSL 2) или Docker Engine + Compose v2 (Linux).
  Проверка: `docker --version` и `docker compose version`.
- **Дамп каталога** `db/ktru_catalog.jsonl.gz` (~344 МБ). В git его нет — положите в папку `db/`.
- **~6 ГБ диска** и **~4 ГБ свободной памяти**. Интернет нужен при первой сборке (образы, пакеты,
  модель bge-m3) и для обращений к нейросетям.
- **Необязательно:** видеокарта NVIDIA с драйвером — эмбеддинги в 10 раз быстрее; ключи нейросетей
  (без них атрибуты извлекаются правилами, остальное работает).

### Запуск одной командой

```bash
docker compose up -d --build
```

Откройте **http://localhost:3000** (документация API — http://localhost:8000/api/docs, открыта только
для этого компьютера). Первый старт: сборка образов ~5–10 мин, загрузка каталога ~20 с —
в шапке «Каталог загружается…», потом «Каталог: 81 509 кодов».

Команда работает и без `.env`: тогда нейросетей нет (атрибуты — правилами) и эмбеддинги на CPU.

### Настройка `.env` (один раз)

```bash
cp .env.example .env
```

В `.env` впишите:

1. **Ключи и модели нейросетей.** `LLM_PROVIDERS` — список через запятую, быстрые первыми; для
   каждого провайдера `<ИМЯ>_API_KEY`, `<ИМЯ>_MODEL`, `<ИМЯ>_PARALLEL`. Готовые блоки с адресами
   tokify, moduleapi, GigaChat и Yandex — в `.env.example`; подобранные модели
   и лимиты — в разделе 11. Yandex для новичка — [docs/YANDEX_SETUP.md](docs/YANDEX_SETUP.md).
2. **GPU** (если есть NVIDIA) — раскомментируйте две строки, и та же команда будет запускать
   Ollama на видеокарте:
   ```dotenv
   COMPOSE_PATH_SEPARATOR=,
   COMPOSE_FILE=docker-compose.yml,docker-compose.gpu.yml
   ```

После правки `.env` — снова `docker compose up -d --build`. Проверка нейросетей:

```bash
docker compose exec backend python check_llm.py
```

У каждого провайдера должно быть `OK за N с`; иначе подсказка: 401 — ключ, 402 — баланс,
404 — модель или адрес, 429 — слишком много потоков.

### Остановить, перезапустить, сбросить

```bash
docker compose stop          # остановить, данные сохраняются
docker compose up -d         # запустить снова
docker compose logs -f backend   # логи обработки: какой провайдер, сколько секунд
docker compose down -v       # удалить контейнеры и данные (задания, кэш каталога)
```

## 2. Запуск без Docker (для разработки)

Удобно, когда правите код и хотите видеть изменения сразу.

### Backend

Нужен Python 3.12 (как в Docker). Пример с `uv`; с обычным `venv` + `pip` то же самое.

```bash
cd backend
uv venv --python 3.12 .venv
uv pip install --python .venv -r requirements.txt pytest==9.1.1 ruff==0.17.1
```

Переменные для локального запуска (PowerShell — `$env:ИМЯ = "значение"`, bash — `export ИМЯ=...`):

| Переменная | Пример                    | Зачем                                                                                              |
| -------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`     | `sqlite:///./dev.db`          | для разработки хватает SQLite; PostgreSQL — `postgresql+psycopg://...`           |
| `CATALOG_PATH`     | `../db/ktru_catalog.jsonl.gz` | путь к дампу                                                                                  |
| `CACHE_DIR`        | `./.cache`                    | куда класть кэш матрицы                                                             |
| `UPLOAD_DIR`       | `./.uploads`                  | временные файлы заданий                                                            |
| `OLLAMA_URL`       | `http://localhost:11434`      | если Ollama запущена локально; иначе поиск только по словам |

```bash
uvicorn api:app --reload --port 8000
```

### Frontend

Нужен Node.js 24.

```bash
cd frontend
npm ci
npm run dev        # http://localhost:5173, запросы /api проксируются на localhost:8000
```

Можно комбинировать: backend, db и ollama в Docker (`docker compose up -d db ollama backend`),
а frontend — через `npm run dev`. Так правки интерфейса видны мгновенно.

## 3. Как пользоваться

1. **Загрузка.** Перетащите один или несколько файлов в зону загрузки или нажмите «Добавить
   файлы». Файлы встают в список: лишний убирается крестиком, неподдерживаемый формат или файл
   больше 10 МБ сразу отклоняется с причиной. Обработка начинается только по кнопке
   «Обработать»; каждый файл становится отдельным заданием, первое открывается, остальные — в
   списке слева. Флажок «Учитывать недействующие коды» включает в поиск отменённые коды.
   Ограничения: 10 МБ и 1000 позиций на файл.
2. **Прогресс и потоковый вывод.** Пока готовых строк нет — кольцо и шаги «Чтение файла →
   Извлечение → Поиск → Уверенность». Как только готова первая пачка (20 строк), появляется
   таблица: позиции можно открывать и исправлять, пока остальные обрабатываются; приходящие
   строки не сбрасывают открытую правку. Кнопка **«Остановить»** отменяет задание: очередь
   пакетов к нейросети снимается, уже обработанные позиции остаются, их можно проверить и
   выгрузить. Страница опрашивает сервер раз в секунду; если связь пропала — «Повторить».
3. **Результаты.**
   - 4 плитки: «Автоматически», «Нужна проверка», «Исправлено», «Принято». Клик по плитке
     фильтрует таблицу.
   - Таблица: исходный текст, извлечённые атрибуты, код и наименование КТРУ, уверенность (число,
     полоска и значок зоны), статус. Код — ссылка на поиск в реестре КТРУ ЕИС (zakupki.gov.ru).
   - «Принять всё от N %» — принимает все действующие коды с уверенностью не ниже порога.
   - Круглая кнопка внизу справа — выгрузка xlsx или csv (для готового или остановленного
     задания).
4. **Панель позиции** (клик по строке или Enter):
   - исходная строка, извлечённые атрибуты и пояснение «почему этот код»;
   - **«Код КТРУ» → «Ввести код вручную»** — любой код каталога, набранный или вставленный
     (пробелы и переносы, как в «10.12.10.000- 00000005» из таблицы, убираются); код проверяется
     по формату и по каталогу, позиция получает статус «Исправлено»;
   - **«Исправить»** — правка наименования, бренда, модели и характеристик; после сохранения код
     подбирается заново по исправленному тексту;
   - если атрибуты извлечены правилами, под ними написана причина: ключ не задан, нейросеть
     не ответила, не успела за бюджет `LLM_BUDGET`, вернула ошибку или пропустила строку;
   - топ-5 кандидатов с кнопкой «Выбрать», поиск по всему каталогу (по коду или словам);
   - «Принять» — подтверждает текущий код.
5. **Клавиатура.** Tab — по элементам, стрелки ↑↓ — по строкам таблицы, Enter — открыть строку,
   Esc — закрыть панель. Видимый фокус у всех элементов.
6. **Темы.** Переключатель в шапке: светлая (туманный серо-голубой фон, «стеклянные»
   карточки, тёмно-синие акценты) и тёмная в том же стиле. Выбор запоминается в браузере.
   Скриншоты: `docs/screenshots/`.

## 4. Как устроено

```
Браузер
   │  http://localhost:3000
   ▼
frontend (nginx :8080 в контейнере) ── статика React; /api/* ──► backend (FastAPI :8000)
                                                                     │
                       POST /api/jobs: файл сохраняется под uuid,    │      ┌──────────────┐
                       в таблицу jobs пишется задание "queued" ──────┼─────►│ PostgreSQL   │
                                                                     │      │ jobs, items  │
             2 потока-воркера внутри backend:                        │      └──────────────┘
             SELECT … FOR UPDATE SKIP LOCKED → берут задание         │
                                                                     ▼
  parser.py ──► extractor.py ─────────► embedder.py ──► search.py ──► confidence.py ──► chooser.py
  файл →        пул нейросетей           bge-m3 в Ollama  косинус +    уверенность %,    второе мнение
  строки        (providers.py) или       (GPU или CPU)    BM25 +       зона, статус      нейросети по
                правила + проверка                        правила                        топ-5 спорных
                по строке                                                │
                                       позиции пишутся в items пачками по 20,
                                       jobs.processed растёт → строки сразу видны в таблице
```

Четыре контейнера (`docker-compose.yml`):

| Сервис | Образ                    | Что делает                                                                               |
| ------------ | ----------------------------- | ------------------------------------------------------------------------------------------------- |
| `frontend` | node:24 → nginx-unprivileged | собирает React, отдаёт статику, проксирует `/api` в backend     |
| `backend`  | python:3.12-slim              | API, очередь, весь конвейер обработки, каталог в памяти |
| `db`       | postgres:16-alpine            | таблицы `jobs` и `items`                                                              |
| `ollama`   | ollama/ollama + bge-m3        | превращает текст в вектор (эмбеддинг)                              |

Нейросеть для извлечения атрибутов — внешняя, по API (адрес и ключ из `.env`).

### Путь одного задания

1. `POST /api/jobs` — проверка размера (≤ 10 МБ), расширения и сигнатуры файла, файл пишется
   на диск под именем `<uuid>.<расширение>`, в `jobs` появляется строка со статусом `queued`.
2. Свободный воркер забирает задание (`FOR UPDATE SKIP LOCKED` — два воркера не возьмут одно
   задание), ставит `processing`.
3. `parser.parse_file` → список позиций `Item(row_number, text, columns)`.
4. `extractor.JobExtractor` кладёт уникальные строки задания в общий пул нейросетей пакетами по
   10 (не больше `2 × слотов` незаконченных пакетов на задание). Поток пула берёт свободный слот
   любого провайдера; пока нейросети отвечают, готовые пакеты идут дальше.
5. Позиции обрабатываются пачками по 20: ждём атрибуты → текст запроса
   `search_text + ". " + исходная строка` → `embedder.embed` → `catalog.search` →
   `confidence.assess` → запись в `items` → `jobs.processed += 20` (строки появляются в таблице).
   Перед каждой пачкой проверяется отмена.
5a. `choose_codes`: строки «Нужна проверка» уходят нейросети с пятью кандидатами; выбранный код
   записывается, только если позицию ещё не правили (раздел 6.6).
6. В конце задание получает `done` (или `failed` с понятной причиной), файл удаляется.
7. Если backend перезапустился посреди задания, при старте оно возвращается в `queued`
   и обрабатывается заново.

## 5. Файлы проекта: кто за что отвечает

```

├── db/ktru_catalog.jsonl.gz     дамп каталога КТРУ (не в git)

│   ├── parser.py                файл → позиции

│   └── Dockerfile
├── frontend/
│   ├── src/                     React-приложение (ниже по файлам)
│   ├── tests/api.test.mjs       тест транспорта api.ts (node --test)
│   ├── Dockerfile               сборка + nginx (конфиг nginx — внутри Dockerfile)
│   └── package.json, vite.config.ts, tsconfig*.json
├── eval/                        синтетический набор 1000 строк и негативные загрузки
├── scripts/evaluate.py          точность сервиса на своём размеченном файле
├── docs/                        YANDEX_SETUP.md, screenshots/
```

## 6. Алгоритмы подробно

### 6.1. Разбор файла (`parser.py`)

- **Шапка** — первая из первых 30 строк, где ≥ 2 непустых ячеек и есть слово из
  `HEADER_WORDS`. Нет шапки → файл читается как текст по строкам.
- **Колонка наименования** — первая ячейка шапки со словом из `NAME_WORDS`, не начинающаяся
  с «код», «№», «артикул» и т. п.; иначе — колонка с самым длинным текстом.
- **Текст позиции** = наименование + колонки-детали (характеристики, бренд, модель, описание)
  через «. ». Все колонки строки сохраняются в `columns` и попадают в выгрузку.
- **Лимиты:** 10 МБ, 1000 позиций, 300 000 ячеек, 200 страниц PDF, 200 МБ после распаковки zip.

### 6.2. Атрибуты (`extractor.py`, `providers.py`)

**Несколько нейросетей.** `LLM_PROVIDERS=gigachat,yandex` перечисляет провайдеров; у каждого свой
лимит одновременных запросов (`GIGACHAT_PARALLEL`, `YANDEX_PARALLEL` → семафор в `Provider`).
Пул `ThreadPoolExecutor` в `extractor.py` имеет ровно столько потоков, сколько слотов у всех
провайдеров, поэтому пакеты по 10 строк стартуют по очереди, а поток берёт свободный слот любого
провайдера (первым — того, кто раньше в списке). Быстрый провайдер сам берёт больше пакетов:
заранее ничего не делится. Повторы с паузой — внутри `providers.chat` (429, 5xx, молчащая
сеть); если провайдер всё равно не справился, пакет уходит к следующему, правила — только
когда отказали все. Провайдер, чья сеть молчит, пропускается 120 с. Кто обработал строку —
`attributes.provider` (виден в панели позиции) и строка `LLM <name>: HTTP 200 in 4.1 s` в логе.
`providers.py` знает три вида API: GigaChat (ключ → OAuth-токен на 30 мин), Yandex AI Studio
(`Api-Key`, папка в `OpenAI-Project`, модель `gpt://<folder>/<model>`) и любой
OpenAI-совместимый (`Bearer`).

1. Одинаковые строки задания отправляются один раз.
2. Строки уходят нейросети **как JSON-данные** `[{id, text}]`; системная инструкция прямо говорит,
   что это данные, а не команды (защита от prompt-injection).
3. Ответ — JSON-массив `{id, name, brand, model, characteristics[{name, value, unit}], search_text}`. `search_text` — родовое название как в КТРУ + «характеристика: значение».
4. **Проверка по строке (`accept`)**: name, brand, model, значение и единица каждой
   характеристики принимаются, только если встречаются в исходном тексте (регистр, ё/е и пробелы
   не важны). Выдуманное отбрасывается. Пустое `name` означает «не товар» — такая строка
   никогда не уходит в «авто».
5. **`measure`** — единица, в которой товар обычно закупают (л, кг, шт…). Это подсказка только для
   поиска (как `search_text`), по строке не проверяется и в атрибуты не выводится.
6. **Запасной путь `rules`**: бренд — латинское слово с заглавной, модель — токен с цифрами после
   бренда, характеристики — «имя значение единица», наименование — текст до первой точки,
   запятой или цифры, `search_text` — сама строка. Причина отката пишется в
   `attributes.fallback` и показывается в интерфейсе:
   | `fallback`    | Когда                                                                                                                                           |
   | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
   | `no_key`      | ключ нейросети не задан                                                                                                          |
   | `unavailable` | нет соединения или ответа; следующие 120 с задания сразу идут на правила, не ожидая |
   | `budget`      | нейросети отвечали, но бюджет задания `LLM_BUDGET` (240 с) закончился                                         |
   | `error`       | HTTP-ошибка (неверный ключ, 401, 5xx) или ответ не разобрался у всех провайдеров                         |
   | `missing`     | нейросеть ответила, но пропустила эту строку                                                                   |

**Важно: нейросеть в проекте используется дважды.** Первая — внешняя, по API: извлекает атрибуты
и пишет `search_text`. Если она недоступна, атрибуты строятся правилами, а точность падает.
Вторая — bge-m3 в Ollama: превращает текст в вектор, по которому ищется код. Она работает
локально всегда. Сам код выбирают точный векторный поиск и правила ранжирования (6.3).

### 6.3. Поиск (`search.py`)

Текст запроса = `search_text + ". " + исходная строка` → вектор bge-m3 (1024 числа).

1. **Точный косинус**: `запросы @ матрица.T` по всем 81 509 кодам, по 128 запросов за раз.
   Недействующие коды маскируются (если флажок не включён). Без HNSW: на этом каталоге он
   терял до 14 % верных кодов.
2. **Гибрид с лексическим поиском**: к 50 ближайшим по косинусу добавляются 20 лучших кодов
   по BM25 над основами слов наименования кода (первые 5 букв — грубая русская морфология).
   Так код с подходящим названием попадает в ранжирование, даже если его вектор не вошёл в 50.
   Лексические кандидаты получают свой настоящий косинус, бонуса за BM25 в балле нет: бонус
   0,01–0,1 снижал точный код на черновом эталоне на 0,3–4,5 п. п. `LEX_LIMIT=0` выключает
   гибрид. Каталог живёт в памяти, поэтому BM25 считается там же, без Postgres FTS.
3. Для каждого кандидата считается итоговый балл:

```
score = cosine
      + 0.02  × (общие слова строки и текста кода: наименование + значения характеристик)
      + 0.01  × (числовые границы строки, равные границам кода: «не менее 1.25» ↔ «> 1.25»)
      − 0.01  × (те же числа, но с другой стороны: «не менее 1.25» ↔ «≤ 1.25»)
      + 0.02  × (неизменяемые значения кода, найденные в строке)
      − 0.04  × (строка называет неизменяемую характеристику, но с другим значением)
      − 0.03  × (у кода особый признак «Да», о котором строка молчит: детское питание и т. п.)
      − 0.015 × (код — шаблон группы)
      − 0.01  × (слова наименования кода, которых нет в строке: «… для детского питания»)
      + 0.005 × (единица строки совпала с единицей кода: «Ед. изм.» из файла, иначе measure)
```

Единица — самый слабый признак: решает только ничьи кодов-близнецов, которые различаются лишь
единицей (кефир в литрах и в килограммах).

4. Сортировка по этой сумме, наружу — **топ-5** (балл обрезается до 1.0 только для показа).

Зачем правила после косинуса: внутри одной группы КТРУ десятки кодов с одинаковым наименованием
и почти одинаковым вектором. Различают их значения характеристик — именно их и сравнивают
правила. «Слово» — 3+ буквы или содержит цифру; латинские буквы-двойники приводятся к
кириллице («A4» = «А4»); для неизменяемых характеристик сравниваются первые 5 букв слова
(«коровье» = «коровьего»).

### 6.4. Уверенность (`confidence.py`)

```
confidence = 100 / (1 + exp(−(20 × top1 + 40 × margin − 16)))
top1   — балл лучшего кандидата
margin — top1 минус балл второго
```

- **Зоны:** ≥ 85 % — `high` (статус `auto`), 60–85 % — `medium`, < 60 % — `low`; medium и low →
  `needs_review`.
- Отменённый код и строка «не товар» никогда не получают `auto`.
- **Пояснение** без нейросети: совпавшие слова, характеристики, числовые границы, статус кода.

Коэффициенты подобраны 20.10.2026 логистической регрессией (процедура описана в
`confidence.py`) на строках чернового эталона, где верный код — не шаблон группы, и на реальной
спецификации: `W_SCORE = 14.5`, `W_MARGIN = 41.5`, `BIAS = -12.2` (было 20 / 40 / −16). Средняя
уверенность стала равна доле верных кодов (88,7 %, было 95,9 % — завышено), точность зоны «авто»
выросла с 90,9 до 92,6 %. Цена: на реальной спецификации одна верная строка ушла из «авто» в
«нужна проверка» (11 → 10 «авто»), коды не изменились.

### 6.5. Очередь (`api.py`)

Без Redis и Celery: очередь — это таблица `jobs`. Два фоновых потока внутри процесса backend
каждую секунду ищут `queued`-задание через `SELECT … FOR UPDATE SKIP LOCKED` и условный
`UPDATE … WHERE status='queued'` (защита от двойного захвата). Ошибка одной позиции → она
`failed` с причиной, задание продолжается. Ошибка базы не убивает воркер — он повторит позже.

Позиции пишутся пачками по 20 строк: готовые строки сразу видны в интерфейсе. Отмена
(`POST /jobs/{id}/cancel`) ставит статус `cancelled`; воркер проверяет его перед каждой пачкой,
а ожидание ответа нейросети прерывается сразу. Пакеты, ещё стоящие в очереди, снимаются; запрос,
ждущий свободного слота, не отправляется; уже отправленный запрос дожидается и выбрасывается.
Завершение задания не перетирает `cancelled`. Слоты запросов к нейросети выдаются строго по
очереди (`FairSlots`): у обычного семафора освободивший слот поток сразу забирал его снова,
и первые пакеты задания ждали до конца бюджета, а таблица оставалась пустой.

### 6.6. Второе мнение по спорным кодам (`chooser.py`)

После основной обработки строки со статусом «Нужна проверка» уходят нейросети пакетами по 5:
текст позиции и пять кандидатов поиска, у каждого — только те характеристики, которыми кандидаты
отличаются. Нейросеть возвращает `{id, code}`; принимается **только код из кандидатов этой
строки** (выдуманный код игнорируется). Позиция меняется условным `UPDATE … WHERE ktru_code =
<код поиска> AND status = 'needs_review'`, поэтому правка, сделанная пользователем во время
обработки, не затирается. Статус остаётся «Нужна проверка», в пояснении — «Код выбран нейросетью
(<провайдер>) из 5 кандидатов поиска». Строки «Автоматически» не перепроверяются: на черновом
эталоне выбор среди уверенных кодов-близнецов был хуже поиска (200 → 192–197 из 274) — у них
одинаковые наименования и данные каталога, различает только признак «шаблон группы».

Замер (реальные прогоны): positions_1000 — категория 82,7 → **85,5 %** (потолок топ-5 85,5 %);
черновой эталон — 73,5 → 73,5 % (нейросеть поменяла 5 кодов: 3 ошибки исправила, верных не
испортила); время на 1000 строк +77 с. Выключение: `LLM_CHOOSE=0`.

| `GET /jobs/{id}`                                                       | задание + `counts` по статусам позиций + `fallback` — сколько строк обработано правилами    |
| `GET /jobs/{id}/items?status=&q=&limit=&offset=`                       | позиции; `status` через запятую, `limit ≤ 200`                                                                                  |
| `PATCH /items/{id}` `{ktru_code}`                                    | ручной выбор или ввод кода (пробелы убираются; код должен быть в каталоге) → `corrected` |
| `PUT /items/{id}/attributes` `{name, brand, model, characteristics}` | правка атрибутов и повторный поиск кода                                                                               |
| `POST /items/{id}/accept`                                              | принять код позиции → `accepted`                                                                                                    |
| `POST /jobs/{id}/accept?min_confidence=`                               | принять все действующие коды не ниже порога                                                                        |
| `POST /jobs/{id}/cancel`                                               | остановить задание в очереди или в работе → `cancelled`; готовые позиции остаются |
| `GET /catalog/search?q=`                                               | поиск по каталогу: по началу кода или словам наименования                                               |
| `GET /jobs/{id}/export?format=xlsx\|csv`                                | выгрузка готового или остановленного задания (409, пока оно в работе)                                         |
| `GET /health`                                                          | `{status, catalog: loading/ready/error, codes, llm: on/off/down}`                                                                                     |

Интерактивная документация — `http://localhost:8000/api/docs`.

## 9. Безопасность

- **Секреты** только в `.env` (в `.gitignore`), ключ нигде не логируется.
- **Загрузка:** лимит 10 МБ и в nginx (12 МБ с запасом), и в API; белый список расширений;
  проверка сигнатуры (xlsx/docx — `PK`, pdf — `%PDF`); файл хранится под uuid; удаляется после
  обработки.
- **Zip-бомбы и огромные файлы:** лимиты распакованного размера, ячеек, строк, страниц.
- **SQL** только через ORM; в поиске экранируются `%` и `_`.
- **Выгрузка:** значения, начинающиеся с `= + - @` (и табуляции), получают префикс `'` —
  защита от формульных инъекций в Excel.
- **Нейросеть** получает строки только как данные; её значения сверяются с исходной строкой.
- **Контейнеры не от root**: backend (uid 10001), nginx-unprivileged, ollama (uid 10002),
  postgres (`user: postgres`).
- **Ссылки в ЕИС** — `target="_blank" rel="noopener noreferrer"`, строятся только для кодов
  правильного вида.
- **Чего нет** (нужно перед публичным деплоем): авторизации, HTTPS, ограничения частоты запросов.
- **Проверка сертификата GigaChat выключена** (`GIGACHAT_VERIFY_SSL=false`), как в примере Сбера;
  перед деплоем включите её с сертификатом Минцифры (раздел 10).

## 13. Как проект делался: решения и отброшенные варианты

1. **Справочник.** Прочитаны модули старого проекта (`b2b`): разбор форматов, проверка по
   строке, точный поиск, уверенность, выгрузка. Код не копировался — переписан проще.
2. **Backend с тестами** → **docker-compose** → **frontend** → **дизайн** → **замеры** —
   каждый шаг отдельным коммитом (`git log`).
3. **Найденные и исправленные ошибки:** воркеры умирали при перезапуске БД; файл задания
   удалялся, даже если статус не записался; nginx запоминал IP backend; выгрузку нельзя было
   сделать с клавиатуры; выгрузка незавершённого задания; postgres запускался от root.
4. **Повышение точности** (каждое изменение проверялось на двух наборах — реальном файле
   и черновике, чтобы не подогнать под один):
   - мягкое уточнение промпта для наименования (без «для …») — атрибуты 81,4 → 82,5 %;
   - сравнение числовых диапазонов — +0,7 п. п. к коду;
   - неизменяемые характеристики и штраф шаблонам — реальный файл 9 → 12 из 12 (две из них —
     ничьи кодов-близнецов), черновик 66,7 → 73,9 %;
   - единица измерения для кодов-близнецов — реальный файл 12 из 12 уже без ничьих, черновик
     73,9 → 74,2 %, группа 96,9 → 97,6 %;
   - штраф за лишние слова наименования кода («… для детского питания») — на сохранённых
     строках без изменений, исправляет почти-ничью при работе без нейросети;
   - ячейки таблицы без шапки склеиваются через «. »: наименование отделено от характеристик.
5. **Отброшено после замеров:**
   - строгий промпт для наименования («до первой характеристики») — наименование 55 → 48 %;
   - «при равенстве брать шаблон» — код 67,0 → 65,6 %;
   - HNSW-индекс вместо точного косинуса — терял до 14 % верных кодов (замер старого проекта).
6. **Новый стиль** интерфейса по референсу: синяя боковая панель, белые карточки, волны-график,
   контурные фигуры; две темы через CSS-переменные.
7. **Новые функции:** ссылка кода в реестр ЕИС, правка атрибутов с повторным поиском кода,
   ручной ввод кода КТРУ, причина работы без нейросети у каждой строки и предупреждение
   в результатах, быстрый откат на правила, когда шлюз нейросети не отвечает.

7. **Ветка `feature/speed-and-ux` (октябрь 2026)** — каждое решение проверено замером:
   - узкое место было не в нейросети, а в эмбеддингах на CPU (236 из 340 с) → GPU-файл compose;
   - пул нейросетей встроен в существующий `ThreadPoolExecutor` (поток на каждый слот провайдера),
     без новых слоёв; обычный семафор отдавал слот одному потоку подряд — первые пакеты голодали;
   - гибридный поиск: BM25 только добавляет кандидатов; бонус BM25 в балле (0,01–0,1) снижал
     точный код на черновике на 0,3–4,5 п. п. — отброшен;
   - гибрид и «правила тождества» из ветки zhenya не взяты: черновик −6,5 п. п. по коду, поиск
     в 10 раз медленнее;
   - модели подобраны пробой; «думающие» qwen/deepseek отброшены (19–90 с на пакет), локальная
     qwen на видеокарте — 42–103 с на пакет;
   - выбор кода нейросетью среди уверенных близнецов отброшен (хуже поиска), оставлен только для
     спорных строк (+2,8 п. п. на positions_1000);
   - 49 из 77 расхождений с черновым эталоном — эталон выбрал шаблон группы, а поиск сознательно
     штрафует шаблоны (это решение подняло реальный файл с 9 до 12 из 12); без выверенного
     эталона менять это правило нельзя.

## 14. Как улучшить

По убыванию пользы.

**Перед деплоем**

1. **Авторизация и HTTPS** — хотя бы basic auth + TLS в nginx или обратный прокси (Caddy/Traefik).
2. **Пароль PostgreSQL** — сменить в `.env`, не оставлять `ktru`.
3. **Ограничение частоты запросов** в nginx (`limit_req`) на `POST /api/jobs`.

## 15. Если что-то не работает

| Симптом                                                                                                                  | Причина и что делать                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `failed to connect to the docker API`                                                                                         | Docker Desktop не запущен — запустите и повторите.                                                                                                                                                                                                                                                                                                                           |
| `port is already allocated` (3000 или 8000)                                                                                | порт занят другим приложением — освободите или поменяйте порт в `docker-compose.yml`.                                                                                                                                                                                                                                                             |
| В шапке «Каталог загружается…» долго                                                            | первый старт читает дамп (~20 с, на медленном диске дольше); смотрите `docker compose logs backend`. «Каталог не загружен» — нет файла `db/ktru_catalog.jsonl.gz`.                                                                                                                                                    |
| В шапке «ключ нейросети не задан: правила», хотя ключ вписан                   | после правки `.env` выполните `docker compose up -d backend`.                                                                                                                                                                                                                                                                                                                     |
| В логах `LLM failed … HTTPStatusError`                                                                                 | неверный ключ авторизации или `GIGACHAT_SCOPE` не подходит к ключу (ключ физлица — `GIGACHAT_API_PERS`). Проверьте значения в `.env` и выполните `docker compose up -d backend`.                                                                                                                                |
| В шапке «нейросеть не отвечает: правила», в логах `LLM is unavailable … ReadTimeout` | шлюз нейросети не отвечает. Задания не ждут: 120 с после сбоя они сразу идут на правила, затем система пробует снова. Проверьте шлюз; уже обработанные строки можно поправить через «Исправить» или загрузить файл позже. |
| В логах `LLM budget is over`                                                                                            | нейросети не успели за `LLM_BUDGET` — добавьте потоков (`*_PARALLEL`) или провайдеров; увеличивать бюджет выше ~270 с нельзя, иначе 1000 строк не уложатся в 5 минут.                                                                                                                                                                                                                                         |
| В логах `LLM failed … HTTPStatusError 429`                                                                             | провайдер ограничил число одновременных запросов: уменьшите его `*_PARALLEL` (GigaChat Freemium — 1).                                                                                                                                                                                                                                                             |
| В логах `LLM <name>: HTTP 402`                                                                                          | у шлюза кончились деньги: пополните баланс. До этого он пропускается, его пакеты берут другие провайдеры. Проверка: `docker compose exec backend python check_llm.py`. |
| Обработка очень долгая                                                                                      | векторы считаются на CPU (1000 строк ~4 мин): запустите с `-f docker-compose.gpu.yml`; нейросеть одна — добавьте провайдеров в `LLM_PROVIDERS`.                                                                                                                                                                                                         |
| 502 в интерфейсе                                                                                                     | backend ещё стартует или упал: `docker compose ps`, `docker compose logs backend`.                                                                                                                                                                                                                                                                                                  |
| Сборка ollama падает                                                                                                | нет интернета при первой сборке — модель bge-m3 скачивается из сети.                                                                                                                                                                                                                                                                                   |
