## Настоящий GigaChat на большом файле

Модель **GigaChat-3-Ultra**, текущие промпт и температура, параллельность 1,
пакеты по 10 уникальных строк, общий бюджет задания 150 с. Настройки не менялись.
Пользователь прямо запросил реальную проверку; имитатор в этих замерах не используется.
Рабочий ключ читался только для авторизации и в отчёты не записывался.

### Проверка извлечения, без поиска и записи в БД

Файл: `b2b/scripts/fixtures/load/spec_1000.xlsx`, **1000 строк, 995 разных текстов**
при текущем parser приложения. Старое описание соседнего проекта про 40 разных строк
не следует переносить на этот прогон: уникальность посчитана заново.

| Показатель | Значение |
|---|---|
| Время извлечения | **150,032 с** |
| Строк с source=llm | **253 / 1000 (25,3%)** |
| Строк с source=rules | **747 / 1000 (74,7%)** |
| Причина резервного режима | Исчерпан бюджет (`budget`) |
| Chat-попытки | 26: 25 ответов HTTP 200; последняя попытка прервана по бюджету |
| Среднее / медиана сетевого chat-вызова | 5,737 / 5,798 с |
| Учтённые токены завершившихся ответов | 15 787 входных + 28 572 выходных = **44 359** |
| Один начальный smoke-запрос | Успешен, 3,114 с с OAuth; 513 токенов |

**Это не полный замер требования скорости:** здесь нет загрузки файла через HTTP,
очереди, эмбеддингов, поиска, БД и выгрузки. Время 150 с нельзя выдавать за время
полной нейросетевой проверки всех 1000 позиций. source=llm также не означает,
что каждое отдельное поле извлечено правильно — это проверяется отдельным сравнением.

При сохранении наблюдаемого темпа 100 пакетов последовательно потребовали бы порядка
580 с только на chat-вызовы. Это оценка, а не выполненный прогон без бюджета.
Результат зависит от провайдера, длины строк и квот; увеличение параллельности
без знания тарифа может дать 429 и само по себе не является исправлением.

## Проверка атрибутов

Использованы существующие синтетические fixtures TXT, CSV, DOCX, PDF, XLSX,
UTF-16 и дубликаты. 13 ожидаемых товаров, 39 полей, 16 уникальных текстов
с учётом служебных строк. Ответы получены живым GigaChat за 10,375 с.
Сравнение нормализует пробелы, регистр и ё/е; для наименования допускает только
варианты, уже перечисленные в expected fixture. Все 13 товаров сопоставлены.

- Наименование: **13/13 = 100%**.
- Бренд: **11/13 = 84,62%**.
- Модель: **11/13 = 84,62%**.
- Общее: **35/39 = 89,74%**. Округлять этот результат до «90%, критерий выполнен» нельзя.

Подтверждённые пропуски:

| Файл | Ожидалось | Получено |
|---|---|---|
| `02_cp1251.csv`, бумага | Бренд «Лист», модель «А4-80» | Пустые бренд и модель |
| `05_multisheet.xlsx`, краска | Бренд «Колор», модель «К1» | Пустые бренд и модель |

Эти значения есть в отдельных колонках исходного файла. parser включает значения
в текст, но убирает названия колонок: например «Бумага офисная. Лист. А4-80…».
Модель не всегда восстанавливает смысл таких фрагментов. Практичное улучшение —
переиспользовать явно заполненные структурированные поля, а не заставлять модель
повторно угадывать их назначение. Промпт и правила в рамках этого аудита не менялись.

Это диагностическая малая выборка. Даже результат выше 90% на ней не заменил бы
измерение на согласованном представительском размеченном датасете.

## Перед презентацией

1. Устранить потери явных атрибутов и снова измерить ≥90% на согласованном эталоне.
2. Разметить точные коды и подтвердить ≥85%; проверить долю ошибок в зоне high.
3. Согласовать смысл ограничения 200 с: допускается ли резервный режим, и при каком
   качестве. Для семантического результата показать режим поиска и долю LLM/rules.
4. Провести повторный большой прогон на готовом окружении, записать время и качество;
   не включать скачивание образов в обработку файла, но подготовить всё заранее.
5. Показать честный сценарий: файл → прогресс → результат → ручная правка → выгрузка,
   с предупреждением о резервном режиме. Подготовить небольшой файл для демонстрации.

## Воспроизведение и артефакты

Живые скрипты требуют явного `--allow-live`, используют текущие настройки GigaChat
и могут расходовать квоту. Пример из корня репозитория:

```powershell
python scripts/live_gigachat_probe.py --project . --file ../b2b/scripts/fixtures/load/spec_1000.xlsx --output reports/gigachat-live-1000-extraction.json --allow-live
python scripts/check_fixture_attributes.py --project . --fixtures ../b2b/backend/tests/fixtures/specs --output reports/gigachat-fixture-attributes.json --allow-live
python scripts/check_live_job.py --base http://127.0.0.1:3000 --file ../b2b/scripts/fixtures/load/spec_1000.xlsx --output reports/live-full-stack-1000.json --allow-live
python scripts/reproduce_audit_findings.py --project . --output reports/confirmed-diagnostics.json
```

Файлы результатов: `gigachat-smoke.json`, `gigachat-live-1000-extraction.json`,
`gigachat-fixture-attributes.json`, `live-full-stack-1000.json`,
`live-full-stack-1000.items.json`, `search-noise-diagnostic.json`, `confirmed-diagnostics.json`.
Скрипты не печатают ключи, Bearer-токены или полные HTTP-заголовки.
