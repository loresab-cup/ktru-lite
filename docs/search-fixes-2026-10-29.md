# Исправления подбора КТРУ — 29.10.2026

## Что изменено

Архитектура, модели, веса ранжирования и число внешних вызовов сохранены.
Изменения затрагивают поиск, уверенность и передачу извлечённых характеристик
из обработки задания и ручного редактирования в поиск.

1. Числовые диапазоны каталога сохраняют название характеристики. Объём RAM
   сравнивается с RAM, SSD — с SSD. Поддерживаются общие сокращения ОЗУ/RAM,
   экран/диагональ и названия единиц в заголовках. Если одно число без названия
   может относиться к нескольким характеристикам, оно не даёт числового бонуса.
2. Слабое совпадение без совпадения названия товара, числовое противоречие и поиск
   только по словам лишают кандидата положительного вклада отрыва в уверенность.
   Такой кандидат требует проверки. Карточка кандидата и итог позиции используют
   одну формулу. Совпадение названия не отменяет запрет при числовом противоречии.
3. Служебное первое слово («для», «при», «нужно» и другие) больше не ограничивает
   список кандидатов. Исправлен случай «Для офиса: ноутбук…».

Формат кэша каталога повышен до 11: прежние метаданные перестраиваются.
Новые библиотеки и сервисы не добавлены.

## Контроль с одинаковыми входными данными

Для сравнения использованы одинаковые сохранённые ответы извлечения и векторы
запросов. Отсутствовавшие ответы и векторы получены через Яндекс с разрешения
пользователя. Эталон не редактировался. Каталог полный: 81 509 кодов.
Офлайн проверялся первый этап поиска с точным скалярным произведением NumPy,
до второго мнения LLM; это не точность полного пользовательского сценария.

В human исключены 230 строк без проверяемого эталона.

Доля auto немного уменьшилась: например, 823 → 812 на основном наборе 1000.
Ошибок среди auto в этом офлайн сравнении осталось 2; на modified — 3,
на human — 1. Правки устраняют конкретные дефекты и не доказывают, что все
автоматические решения правильны. Проценты остаются оценкой алгоритма,
а не независимо откалиброванной вероятностью для любого товара.

Условия: один контрольный файл без параллельной пользовательской нагрузки,
готовый каталог, batch=20, настроенные пять ключей Яндекса. Worker перезапущен

складывать для получения общего времени. Время включает загрузку и опрос HTTP.
Это одиночный замер, а не гарантия для пяти одновременных загрузок.

Проверка создаёт временную учётную запись напрямую в БД и принимает согласия
через HTTP; интерфейс регистрации этим запуском не проверяется.
PDF синтетический, 12 примеров атрибутов не подтверждают ≥90% на произвольных
товарах. Точность живых ответов LLM может отличаться между запусками.
