# Яндекс в приложении

В `.env`:

```dotenv
LLM_PROVIDER=yandex
LLM_PARALLEL=4
YANDEX_BASE_URL=https://ai.api.cloud.yandex.net/v1
YANDEX_API_KEY=
YANDEX_FOLDER_ID=
YANDEX_MODEL=qwen3.6-35b-a3b
```

Заполните секретный ключ и ID каталога локально. В данной сессии они уже сохранены
из предыдущей настройки, повторное посещение сайта не требуется. `.env` исключён из Git.
Старые `GIGACHAT_*` и `ANTHROPIC_*` остаются для возврата, но в Яндекс не передаются.

Применение:

```powershell
docker compose up -d --build --no-deps backend
```

В интерфейсе http://localhost:3000 достаточно загрузить спецификацию как обычно.
Модель работает на стороне Яндекса; сайт AI Studio и отдельный агент для обработки
не нужны. В запросе каждый раз передаётся существующая системная инструкция проекта.
Для Qwen отключены рассуждения (`reasoning_effort=none`); сохраняются проверка значений
по исходному тексту, бюджет 150 секунд и резервные правила. Неполный ответ не считается
успешным. Изолированный тест и полный тест приложения имеют разный охват замеров.

Короткая проверка текущего поставщика: `scripts/check_configured_model.py` внутри
backend-контейнера с `--allow-live`. Полный тест загрузки, поиска, базы и экспортов:
`scripts/check_live_job.py --allow-live --file <spec.xlsx> --output <report.json>`.

API платный по обычному тарифу, если льготы аккаунта не покрывают расходы. Финальные
списания и наличие грантов нужно смотреть в кабинете. Успешное извлечение 1000 строк
не доказывает правильность кодов КТРУ: для этого нужен размеченный эталон.
