# DeepSeek: один API-ключ

## Через Яндекс AI Studio

Для оплаты через Яндекс используйте существующий ключ Яндекса и его каталог:

```dotenv
LLM_PROVIDERS=yandex2
YANDEX2_API_KEY=
YANDEX2_FOLDER_ID=
YANDEX2_MODEL=deepseek-v4.1-flash/latest
YANDEX2_REASONING_EFFORT=none
YANDEX2_PARALLEL=4
YANDEX_TOTAL_PARALLEL=4
LLM_BATCH=5
LLM_COMPACT=1
LLM_LOCAL_STRUCTURED=1
LLM_REQUEST_TIMEOUT=60
LLM_RETRIES=1
```

Это отдельный от прямого DeepSeek API маршрут. `DEEPSEEK_API_KEY` здесь не используется.
Адрес Яндекса наследуется из `YANDEX_BASE_URL` (по умолчанию
`https://ai.api.cloud.yandex.net/v1`). Приложение формирует полный `gpt://` URI модели и
передаёт каталог в `x-project`. В этом API рассуждения отключаются через
`reasoning_effort: none`. Используется совместимый Chat Completions API; менять весь
проект на Responses API не требуется.

Проверка: `docker compose run --rm --no-deps backend python check_llm.py yandex2`.
Затем, дождавшись завершения активных заданий: `docker compose up -d --no-deps backend`.
Одиночный запрос проверен успешно. Пачка из 5 товаров также проверена: 5/5 строк от модели,
18,35 с, без reasoning-токенов. Пачки по 20 в полном прогоне не уложились в таймаут 40 с
и дали резервные правила на всех 100 строках; этот прогон не подтверждает качество DeepSeek.
Контрольный запрос на те же 20 товаров с ожиданием 90 с завершился успешно за 55,98 с:
20/20 строк от модели, reasoning-токенов нет. Это подтверждает недостаточный таймаут
для прежнего размера пачки, а не ошибку ключа или URI модели.
Финальный компактный режим на тех же 100 строках: 47 с, 100/100 строк от DeepSeek,
96/100 точных кодов, около 12,41 ₽ до скидок. Полный протокол:
[сравнение режимов](deepseek-optimization-2026-10-28.md).
Последующий гибридный режим проверен на всех 1000 товарах: 183,24 с, 970/1000 точных кодов,
856 структурированных строк локально и 144 через DeepSeek, около 47,82 ₽ до скидок.
[Полный замер](structured-optimization-2026-10-28.md).
Четыре запроса прошли без 429 на этом аккаунте; для другого аккаунта
квоту нужно проверить отдельно.

## Напрямую через DeepSeek

Готовая модель извлекает атрибуты товаров по системному промпту проекта. Обучение весов
не выполняется. Поиск кода КТРУ по-прежнему использует локальный каталог и bge-m3.

`LLM_COMPACT=1` включает короткие поля и тройки характеристик. Backend восстанавливает
обычные атрибуты и собирает `search_text` из родового названия и проверенных значений.
Полное название сохраняется, если короткая категория теряет его уточнения; явная единица
закупки из строки имеет приоритет над догадкой модели. Пустые поля не генерируются.
`LLM_COMPACT=0` возвращает прежний формат для сравнительного замера.
Одинаковые строки внутри задания уже объединяются и отправляются один раз; порядок
и число позиций в результатах сохраняются. Результаты между разными заданиями не кэшируются.

`LLM_LOCAL_STRUCTURED=1` пропускает платное извлечение для явно структурированных строк,
если название точно есть в каталоге. Явные поля бренда/модели, латиница в названии,
неоднозначные имена характеристик и свободный текст остаются DeepSeek. Источник таких
атрибутов — `structured`, без `provider` и `fallback`: это штатный разбор, не сбой модели.
Эмбеддинги, числовые проверки, ранжирование и второе мнение сохраняются.
Для структурированных строк `search_text` содержит только наименование: API добавляет
полный исходный текст со всеми характеристиками. Это устраняет двойную обработку
характеристик локальной bge-m3 и не удаляет их из запроса поиска.

В корневом `.env` заполните:

```dotenv
LLM_PROVIDERS=deepseek
DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_PARALLEL=4
DEEPSEEK_RPM=0
```

Ключ создаётся в [кабинете DeepSeek](https://platform.deepseek.com/api_keys).
API оплачивается отдельно от пользовательского чата. Ключ хранится только в `.env`,
не передаётся во фронтенд и не включается в репозиторий.

`DEEPSEEK_PARALLEL=4` означает четыре одновременных запроса с одним ключом.
Настройка действует на весь процесс backend, в том числе на несколько заданий и второе
мнение. Дополнительные аккаунты не нужны. При 429 уменьшите параллельность и задайте
`DEEPSEEK_RPM` согласно ограничениям аккаунта. Параллельность не гарантирует время обработки.

Для проверки без переключения основного backend на новые настройки:

```bash
docker compose build backend
docker compose run --rm --no-deps backend python check_llm.py deepseek
```

После успешной проверки, дождавшись завершения активных заданий:

```bash
docker compose up -d --no-deps backend
```

Используется только DeepSeek: сохранённые ключи других сервисов не задействуются, пока их
имена не добавлены в `LLM_PROVIDERS`. При отсутствии ключа или сбое модель заменяют локальные
правила; причина видна в результатах. Такой прогон нельзя считать полностью нейросетевым.

Thinking выключен явно через `thinking: {type: disabled}`: по умолчанию API его включает.
Ответ остаётся JSON-массивом в существующем формате приложения; режим `json_object`
не включается, поскольку он требует другого корневого формата. Проверка значений по исходной
строке и обработка обрезанных/некорректных ответов сохраняются.

Следующий замер: один и тот же набор из 100 строк, затем 1000, с фиксацией полного времени,
точности КТРУ, доли `source=llm`, резервных правил и ошибок API. До такого замера скорость
и качество DeepSeek для этого проекта не подтверждены.

Официальная документация: [запросы](https://api-docs.deepseek.com/quick_start),
[thinking](https://api-docs.deepseek.com/guides/thinking_mode/),
[цены](https://api-docs.deepseek.com/quick_start/pricing/).
