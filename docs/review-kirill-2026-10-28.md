# Ревью изменений Кирилла: модели и поиск

Продолжение: по следующему запросу пользователя выполнены сравнение размеров пачки,
рефакторинг и настройка YandexGPT. Итоги — в
[отчёте о настройке backend](yandex-batch-refactor-2026-10-28.md).
Утверждения ниже о неизменённом коде относятся к моменту первоначального ревью.

Дата: 28 октября 2026. Проверена локальная `main` на `1ee8f60`.
Повторная проверка папки `db` после сообщения пользователя: файл векторов уже
присутствует (90 312 482 байта). Проверены 81 509 уникальных кодов, матрица
81 509 × 256 float32, отсутствие NaN/Inf и нулевых векторов. Все коды и их порядок
совпадают с текущим дампом, пропущенных и лишних кодов нет. Блокировка по отсутствию
файла, описанная ниже на момент первой проверки, снята. Это проверка структуры
и соответствия кодов, не независимая проверка происхождения модели векторов.
Основные изменения моделей: `d2b17bf`, `e891561`; также просмотрены текущие
`providers.py`, `extractor.py`, `embedder.py`, `search.py`, compose и отчёт Кирилла.

## Вывод

Изменения нельзя считать просто неудачной заменой DeepSeek на «Алису».
В `.env` сейчас стоит `yandexgpt-5.1`, а не `aliceai-llm-flash` и не OpenAI GPT.
Кирилл отдельно изменил модель разбора строк и модель векторного поиска.
Облачный поиск устраняет требование к видеокарте, что подходит сдаче на неизвестном
оборудовании. Однако переносимость подключения других LLM ухудшилась.

Вернуть DeepSeek через Яндекс технически можно. Одной строки модели недостаточно
для восстановления прежнего быстрого режима: удалена настройка рассуждений,
таймаут теперь фиксированный, компактного ответа и структурного разбора в этой ветке нет.
Менять модель без сравнительного замера качества не рекомендуется.

## Найденные проблемы

### P1. Удалена возможность отключить рассуждения DeepSeek

В `e891561` из `Provider`, загрузки окружения и `providers.body()` удалён
`reasoning_effort`. Переменная `YANDEX2_REASONING_EFFORT=none` теперь ничего не делает.
Модель через `YANDEX2_MODEL=deepseek-v4.1-flash/latest` загрузится, но запрос уйдёт
без отключения рассуждений. Это подтверждено коротким реальным запросом на текущем
промпте извлечения атрибутов:

| Вариант | Время | Выходные токены | Из них рассуждения |
| --- | ---: | ---: | ---: |
| YandexGPT 5.1 | 1,12 с | 160 | не указаны |
| DeepSeek, тело запроса как в новой версии | 21,88 с | 1109 | 1002 |
| DeepSeek с `reasoning_effort=none` | 2,30 с | 120 | 0 |

Запрашивалась одна строка бумаги А4, не пользовательский датасет.
Все три приведённых ответа: HTTP 200, завершение `stop`, непустой ответ с атрибутами.
Это проверка совместимости и конкретный пример лишних затрат, не статистический
тест скорости или точности на 1000 строк. Кэш, порядок запросов и разброс ответов
не позволяют переносить соотношение времён на весь проект.

Исправление: вернуть необязательную настройку рассуждений на провайдера, передавать
её только когда задана; для DeepSeek через Яндекс использовать `none`.

### Снято повторной проверкой: отсутствие файла векторов

Новый compose требует `db/ktru_vectors_yandex.npz`. Локально есть дамп каталога,
но этого файла нет. `search.load_catalog()` явно выдаёт `FileNotFoundError`
до построения каталога. Переменная модели извлечения атрибутов это не исправляет.

Это документированное новое требование, а не скрытая ошибка алгоритма. Однако
перед запуском именно на этой машине оно блокирует обновление. Нужно получить
векторный файл, соответствующий дампу, либо построить его штатным скриптом.
Строить заново платными запросами ко всему каталогу в рамках ревью не запускалось.

### P2. Удалены настройки, необходимые для прежнего режима DeepSeek

`REQUEST_TIMEOUT=40` и `RETRIES=2` теперь константы. Прежние `LLM_REQUEST_TIMEOUT`
и `LLM_RETRIES` не читаются. При текущем `LLM_BATCH=20` замена модели не воспроизводит
ранее проверенные настройки DeepSeek: небольшие пачки, отсутствие рассуждений,
настраиваемый таймаут. Насколько часто новые пачки будут превышать 40 секунд,
в этом ревью не измерялось.

В `e891561` также удалён общий OpenAI-совместимый провайдер: имя `deepseek` в
`LLM_PROVIDERS` будет пропущено. Для DeepSeek **через Яндекс** сохраняется рабочий путь
через `yandex`/`yandex2` и соответствующее поле модели. Прямой DeepSeek API — другой
путь авторизации, его одной строкой `DEEPSEEK_MODEL` теперь не подключить.

## Что в изменениях обосновано

- Независимость от видеокарты обеспечивается облачными эмбеддингами, а не выбором
  YandexGPT вместо DeepSeek для атрибутов. Эти две настройки надо оценивать отдельно.
- По отчёту Кирилла, после перехода на Yandex embeddings: 981/1000 точных кодов
  за 222 с; human-набор — 752/770 за 214 с; изменённые 1000 строк — 978/1000 за 238 с.
  Это его сохранённые измерения, в этом ревью повторно не воспроизводились.
- Наш предыдущий human-прогон: 744/770 за 234 с; организаторский — 970/1000
  примерно за 182 с. Условия различаются: изменены поиск, эмбеддинги и настройки.
  Приписывать разницу только YandexGPT или только DeepSeek нельзя.
- Удаление локального структурного разбора объяснено в отчёте офлайн-регрессиями.
  Возвращать оптимизацию автоматически без замеров на текущем поиске было бы неверно.
- Очередь, отмена, контроль значений по исходному тексту и общий JSON-контракт
  атрибутов сохранились. Весь backend не привязан к одному формату ответа «Алисы»;
  ограничение находится главным образом в настройках провайдеров.

## Что фактически запущено на машине

После запуска пользователем Docker проверен работающий контейнер. Он собран из
**старого кода**, не из текущей `main`: хеш `providers.py` отличается, используется
один `yandex2` с DeepSeek и четырьмя параллельными запросами, эмбеддинги имеют
размерность 1024, запущена Ollama. В новом исходном коде размерность 256 и Ollama нет.
На момент проверки health: каталог ready, 81509 кодов, LLM on, embeddings down.
Следовательно, состояние этого контейнера не доказывает работоспособность новых коммитов.

## Рекомендованный следующий шаг

Сохранить текущую `main` для сравнения. Сначала обеспечить файл векторов для нового
поиска. Вернуть необязательные настройки рассуждений и таймаута, затем провести
сопоставимый прогон YandexGPT и DeepSeek на одинаковых входах, поиске и числе слотов.
Сравнивать точные коды, ошибки в авто, время, fallback и фактические токены.
Без такого прогона утверждение «DeepSeek лучше» или «Алиса лучше» не подтверждено.

В рамках ревью `.env`, исходный backend и работающие контейнеры не изменялись.

diff, проверка настроек/артефактов, health работающего старого образа и короткие
API-пробы. Ключи в отчёт не включены. Git commit/push не выполнялись.
