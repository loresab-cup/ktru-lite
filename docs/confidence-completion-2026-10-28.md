# Процент для итогового кода после второго мнения

После выбора другого кандидата нейросетью pipeline раньше сохранял confidence=null.
Теперь процент рассчитывается для выбранного кода по той же формуле, которая уже
используется в карточках кандидатов: score этого кода и его разница с сильнейшим
конкурентом. Используется raw_score до ограничения 1.0, если он сохранён.

Формула, веса и пороги не изменены. Второе мнение не получает произвольной надбавки
и не выдаёт самооценку за вероятность. При конфликте поиска и модели процент может
быть низким, вплоть до 0 после округления. Статус остаётся needs_review независимо
от выбранного кода. Пояснение в карточке описывает основу оценки.

Оценка не является независимо откалиброванной вероятностью правильности. Это
существующая алгоритмическая оценка поддержки кодом поиска; область её применения
к альтернативам уже использовалась в карточках кандидатов.

Ручной выбор и запомненное решение человека остаются отдельным источником:
выдуманные 100% им не присваиваются. Строгая приёмка требует конечное число 0–100
для алгоритмических предложений; источник remembered и ручные статусы учитываются
отдельно. Неизвестный код вне списка кандидатов не получает выдуманной оценки.

Отмена правки и возврат исходного предложения восстанавливают процент для старых
снимков, если в них он отсутствовал, а кандидат и его оценки сохранены.
Защита от перезаписи одновременной ручной правки сохранена.

## Проверки

- 211 backend-тестов прошли, 10 пропущены из-за отсутствующих старых fixtures;
  включены проверки PostgreSQL/pgvector на отдельном сервере. Ruff check/format прошли.
- Две frontend-проверки, lint, TypeScript и production build прошли.
- Проверены совпадение процента в списке и карточке кандидата, raw_score выше 1,
  отрицательная разница с конкурентом, неизвестный код, конкурентная ручная правка,
  восстановление старых снимков, отказ приёмки на null/NaN/inf/некорректных значениях.
- На 9102 сохранённых строках из 18 файлов старые verdict первого кандидата и
  оценки карточек совпали полностью. В этих сохранённых прогонах есть 220 пропусков,
  которые можно заполнить по прежним кандидатам без запросов к моделям.

Это сравнение расчёта на сохранённых данных, не новый живой замер точности.
Дополнительные LLM/embedding-запросы для заполнения процентов не нужны.

Итог применения к рабочей базе и JSON проверки: [confidence-fix-2026-10-28.json](../eval/reports/confidence-fix-2026-10-28.json).

В рабочей базе заполнены 112 пропусков. Из 8186 алгоритмических предложений в
завершённых заданиях все имеют корректный процент. Хеш всех пар код/статус до и
после совпал. Для каждой из 112 записей проверен расчёт; для пяти — ответ рабочего
HTTP API через frontend и совпадение с карточкой кандидата. Подсказка есть в
собранном интерфейсе. Резервная копия прежних записей — локально в
`outputs/confidence-fix/existing-before.json`, исключена из Git.
