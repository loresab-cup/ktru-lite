# Пять аккаунтов Yandex AI Studio

Ключи вставляются в **`.env` в корне проекта**, не в Python-код и не в frontend.
Для каждого участника нужны API-ключ сервисного аккаунта и ID каталога (`FOLDER_ID`),
в котором этому аккаунту разрешено вызывать модели. Обычного логина Яндекса недостаточно.
У сервисного аккаунта должна быть роль `ai.languageModels.user` для нужного каталога.

Для пяти участников с отдельными облаками и независимыми квотами:

```dotenv
LLM_PROVIDERS=yandex,yandex2,yandex3,yandex4,yandex5,gigachat

YANDEX_API_KEY=
YANDEX_FOLDER_ID=
YANDEX2_API_KEY=
YANDEX2_FOLDER_ID=
YANDEX3_API_KEY=
YANDEX3_FOLDER_ID=
YANDEX4_API_KEY=
YANDEX4_FOLDER_ID=
YANDEX5_API_KEY=
YANDEX5_FOLDER_ID=

YANDEX_MODEL=aliceai-llm-flash
YANDEX_PARALLEL=1
YANDEX_TOTAL_PARALLEL=5
YANDEX_RPM=0
```

Справа от `=` впишите соответствующее значение без угловых скобок. У первого аккаунта нет
цифры `1` в имени переменной. Пустой `YANDEX2_FOLDER_ID` наследует `YANDEX_FOLDER_ID`;
для пяти отдельных облаков заполните все пять ID. Ключи друг от друга **не наследуются**.

Поля модели, адреса, параллельности и RPM для аккаунтов 2–5 наследуются из `YANDEX_*`.
При необходимости их можно переопределить, например `YANDEX2_MODEL=yandexgpt-5.1`.
Модель задаётся коротким именем из галереи; код сам строит `gpt://FOLDER_ID/имя-модели`.
Можно указать и полный URI. По умолчанию используется OpenAI-совместимый адрес
`https://ai.api.cloud.yandex.net/v1`; API-ключ передаётся через Bearer, каталог — через `x-project`.

Модель `aliceai-llm-flash` поддерживается текущей документацией. Альтернатива — `yandexgpt-5.1`.
Скорость и точность на закупочных данных необходимо измерить после получения ключей.
Старую YandexGPT Lite 5 не используйте для нового подключения: объявлено отключение 15.11.2026.

## Как распределяется файл

1. Пользователь загружает один файл, сервер сохраняет исходный порядок строк.
2. Уникальные строки делятся на пачки `LLM_BATCH=20`.
3. Общая очередь отправляет пачки свободным аккаунтам. До пяти запросов выполняются одновременно.
4. Быстрые аккаунты получают следующие пачки; жёсткого деления «каждому ровно пятая часть» нет.
5. Ответы сопоставляются с исходными строками и собираются в одно задание.
6. Для недоступного провайдера сохраняются паузы, повторы и резервное извлечение с явной причиной.

Это параллельные запросы в пуле фоновых потоков; интерфейс и очередь заданий не блокируются.
Отдельный длительный асинхронный API Yandex с операциями и опросом результата здесь не используется.

`YANDEX_PARALLEL` ограничивает один ключ. `YANDEX_TOTAL_PARALLEL` — общий предел всех Yandex-ключей
в одном backend-процессе, включая одновременные задания. Для одного облака в примере установлен
консервативный предел **2**. Пять ключей одного облака не увеличивают его общую квоту.
Для пяти независимых облаков с разрешённой параллельностью минимум 1 на облако поставьте **5**.
Ограничения запросов в минуту задаются отдельно, например `YANDEX2_RPM=60`, если это нужно вашей квоте.
Количество ключей не гарантирует пятикратного ускорения: остаются время модели, Ollama и поиск.

## Применить настройки и проверить

После заполнения `.env` из корня проекта:

```powershell
docker compose up -d --build backend
docker compose exec backend python check_llm.py yandex yandex2 yandex3 yandex4 yandex5
```

Диагностика отправляет каждому провайдеру одну короткую синтетическую товарную строку;
ключи не выводятся. Успех настройки проверяется реальным ответом, а не наличием имени в `/api/health`.
Чтобы проверить именно Яндекс без GigaChat, временно оставьте в `LLM_PROVIDERS` только пять `yandex*`.
Полный замер на файлах выполняйте после успешной диагностики; сохраняйте долю `fallback`,
время и точность. Зелёный тест с HTTP-моками не доказывает доступность реальных ключей.
