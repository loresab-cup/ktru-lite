# Где искать код backend

FastAPI принимает запросы, Celery выполняет задания через Redis. PostgreSQL хранит результаты и векторы pgvector. Подробности — [архитектура кейса 5](case5-architecture.md).

```text
backend/
  api.py          сборка приложения, middleware, жизненный цикл
  access.py       контекст проверенного пользователя и фильтр владельца
  privacy.py      версии и история отдельных согласий
  database.py     подключение и фабрика сессий
  models.py       таблицы заданий, позиций и решений
  runtime.py      настройки, каталог, сигналы остановки
  workers.py      загрузка каталога, очистка и подготовка приложения
  tasks.py        Celery, восстановление и защита от повторной обработки
  job_queue.py    публикация заданий в Redis
  vector_store.py импорт и точный SQL-поиск векторов pgvector
  job_store.py    захват задания, прогресс и завершение в базе
  pipeline.py     обработка спецификации и подбор кодов
  decisions.py    запоминание и отмена решений человека
  parser.py       чтение загруженных файлов
  extractor.py    извлечение атрибутов
  providers.py    обращения к моделям
  embedder.py     векторы текста
  search.py       поиск кандидатов в каталоге
  characteristics.py  единицы измерения и сравнение характеристик
  catalog_data.py  чтение кэша и векторного файла
  confidence.py   оценка уверенности
  chooser.py      второе мнение для спорных позиций
  auth.py         пароли, пользователи и сессии
  exporting.py    кодирование CSV/XLSX и защита от формул
  migrate.py      безопасное обновление схемы
  migrations/     версии схемы Alembic
  routes/
    __init__.py   подключение маршрутов
    accounts.py   вход, регистрация, выход
    jobs.py       загрузка, задания, прогресс и отмена
    items.py      позиции, ручные правки и подтверждение
    catalog.py    каталог и состояние сервиса
    exports.py    выгрузка результатов
    common.py     общие HTTP-проверки и сериализация
```

Типовые изменения:
- Новый формат файла — parser.py.
- Новый провайдер — providers.py.
- Изменение алгоритма подбора — search.py или pipeline.py с замерами.
- Ошибка отмены/повторного захвата задания — job_store.py и tasks.py.
- Ручное исправление позиции — routes/items.py; память решений — decisions.py.
- Новая колонка базы — models.py и новая миграция.
- Новый адрес API — соответствующий файл routes, без добавления логики в api.py.

Маршруты вызывают обработку и операции базы. Обработка не импортирует HTTP-маршруты.
Все используют одни database и runtime; отдельных подключений или копий каталога
на каждый раздел нет. Не создавайте второй роутер приложения или второй пул очереди.

Исторические результаты разделения API относятся к прежней архитектуре. Актуальные проверки Celery/pgvector и ограничения описаны в [отчёте по кейсу 5](case5-architecture.md).
