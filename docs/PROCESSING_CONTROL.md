# Загрузка, запуск и остановка

Файлы загружаются отдельно от запуска. После проверки списка нажмите «Обработать».
Несколько файлов создают несколько заданий в существующей очереди. Результаты каждого
доступны в недавних заданиях. Удаление доступно до запуска; уже остановленное задание
не запускается повторно — загрузите файл заново, если это необходимо.

Состояния: загрузка в браузере → `uploaded` → `queued` → `processing` → `done`.
Остановка: `queued/uploaded` → `stopped`, `processing` → `stopping` → `stopped`.
Ошибка обработки: `failed`; готовые до ошибки результаты доступны.

Остановка отменяет ожидающие пакеты извлечения, ожидание семафора и следующие
повторы HTTP-запросов. Чтение проверяет отмену между строками Excel, страницами PDF
и товарными строками. Синхронные HTTPX-запросы уже в сети не имеют отдельной отмены:
они могут завершиться или истечь по тайм-ауту. После них новая работа не начинается.
Уже выполняющийся расчёт поиска заканчивает текущий пакет и сохраняет готовые строки.
Остановка действует внутри одного backend-процесса; несколько процессов с общей БД
по-прежнему требуют отдельного механизма владения заданиями.

Каждый сохранённый пакет содержит до 100 позиций. Идентификатор позиции в БД остаётся
неизменным. В `attributes.source_index` хранится порядок позиции во всём файле:
номера строк на разных листах Excel могут совпадать. При восстановлении после перезапуска
готовые позиции пропускаются, их коды, атрибуты и статусы не перезаписываются.
Для заданий старой версии без `source_index` используется прежний номер строки;
восстановление старого незавершённого многолистового файла требует ручной проверки.

`POST /api/jobs` по умолчанию сохраняет файл без запуска. Старый автоматизированный
клиент может явно передать `auto_start=true`; интерфейс этим режимом не пользуется.
`POST /api/jobs/{id}/start` атомарно меняет только `uploaded` → `queued`.
Готовая часть выгружается через прежний endpoint, включая обработку, остановку и ошибку.

При разработке `API_PROXY_URL` задаёт адрес backend для Vite; по умолчанию это
`http://localhost:8000`. В Docker используется прежний nginx.

Для замера полного процесса используйте `scripts/check_live_job.py`: он поддерживает
старую и новую схемы запуска, считает время от начала отправки файла до конечного
состояния, сохраняет число строк с атрибутами модели и причинами резервного режима.
`stage_seconds.extract` — ожидание извлечения, перекрывающегося с поиском;
`embed`, `search`, `confidence`, `save` в новой версии считаются отдельно.
`upload` на сервере исключает сетевую передачу multipart; полное время берите из
внешнего замера. Время ручной проверки списка до нажатия кнопки не является очередью.

`scripts/benchmark_retrieval.py` — отдельная синтетическая диагностика поиска:
она берёт названия и векторы самого каталога. Это не независимая оценка реальных
закупок, не замер генерации эмбеддингов и не подтверждение полного лимита 200 секунд.
