# Практическое сравнение до и после разделения backend

Сравнивались сохранённый api-before.py и новый backend. Изолированный контейнер
без сети; отдельная SQLite-база на каждый запуск, одинаковый каталог из двух
кодов, 1000 строк, правила вместо внешних моделей. Выполнено 8 запусков каждого
варианта с чередованием порядка; первый раунд исключён из медиан.

Во всех 8 парах совпали все 1000 позиций, коды, уверенность и кандидаты,
байты CSV и значения всех ячеек XLSX. Проверялись загрузка, захват задания,
обработка, чтение, ручное исправление с отсутствующей алгоритмической уверенностью,
отмена изменения и обе выгрузки.

| Операция, медиана | До | После |
| --- | ---: | ---: |
| Создание новой схемы | 75,50 мс | 186,47 мс |
| Загрузка файла | 31,79 мс | 37,89 мс |
| Обработка 1000 строк | 1025,35 мс | 1107,83 мс |
| Чтение 200 позиций | 42,22 мс | 41,41 мс |
| Ручная правка | 19,65 мс | 17,70 мс |
| CSV | 59,61 мс | 59,74 мс |
| XLSX | 207,88 мс | 259,86 мс |

Ускорение не подтверждено. Обработка в этом локальном сценарии медленнее примерно
на 82 мс (8%), создание схемы дороже из-за миграций. Различия микрозамеров зависят
от CPU/диска/прогрева; даже общий код XLSX показывает разброс. Они не доказывают
такой же разницы на настоящем каталоге и облачных моделях. Платные запросы не выполнялись.

Практическая польза изменения — сохранение поведения при явных границах модулей
и проверяемое обновление базы. Ранее подтверждены 194 passed, 10 skipped,
идентичный OpenAPI, создание и обновление базы, конкурентные миграции и отказ
неподходящей схемы. На копии и рабочей базе сохранены контрольные суммы данных.

Дополнительно проверены зависимости 18 корневых Python-модулей: циклов импортов
не найдено. api.py — 65 строк, routes.py — 719, pipeline.py — 455. Последние два
ещё крупные: дальнейшее разделение возможно, но выигрыш скорости от самого
разнесения функций по файлам ожидать не следует.

Исходные замеры: outputs/migration-work/refactor-benchmark.json (локальный файл).
