## Изменения

- Резервный поиск: если наименование лучшего кандидата потеряло начальное слово товара,
  кандидаты повторно ранжируются внутри названной группы, с прежними весами и числовыми правилами.
  Это исправляет пары «клавиатура USB чёрная → чай», «ноутбук 16 ГБ → калибратор»,
  «мышь с проводом 1,5 м → мазут». Предположение о начальном слове не универсально.
- Векторный поиск: явно написанное название каталога возвращается в подбор, если лучший
  кандидат потерял слова этого названия. Более конкретные названия, содержащие эти слова,
  сохраняются. Косинусы настоящие, веса и пороги не менялись.
- Ручной каталог фильтрует недействующие коды до ограничения выдачи. Совпадение начинается
  на границе слова: «стул» больше не находит «фистульный». Ответ остаётся списком;
  подпись «В выдаче» не выдаёт ограниченный список за общее количество совпадений.
- Ручная замена кода сохраняет `confidence=null`; интерфейс показывает «—» с пояснением,
  экспорт оставляет процент пустым. Принятие не создаёт фиктивную оценку. Отмена восстанавливает
  исходный код и его оценку.
- Проверка позиций идёт по `needs_review/failed`, с возвратом к началу. Обычная навигация
  вверх/вниз по всем строкам сохранена.
- Массовое принятие явно подписано как действие по всей спецификации независимо от фильтров.
  Ограничения по действующему коду, наличию товара и порогу сохранены.
- Ошибки истории и каталога отделены от пустого списка; есть повтор загрузки.
  Новая поисковая строка сразу скрывает результаты предыдущего запроса. Аналогичные состояния
  исправлены в поиске и проверке кода внутри карточки позиции.
- Автоматические назначения больше не описываются как проверенные человеком.
- Исходное наименование видно в результатах; полный файл доступен в подсказке карточки истории.
  Убрано глобальное уменьшение страницы `zoom: .9`, подпись выгрузки видна на desktop,
  обучение запускается по кнопке.
- Одноколоночный CSV с точным заголовком «Наименование» больше не включает заголовок в товары.
- Диагностика LLM различает отказ OAuth и chat; HTTP 401 не объявляется доказанно неверным ключом.
- Ошибка Google `FAILED_PRECONDITION` включает паузу провайдера вместо повторения отказа
  на каждой партии. Подтверждённый ответ Google: `User location is not supported for the API use.`
- Короткое название без характеристик и модели требует ручной проверки при нескольких
  кандидатах, даже если разрыв похожести большой. Уверенность не подменяется, причина видна в пояснении.

## Переход на Yandex AI Studio

По следующему запросу пользователя добавлены пять Yandex-провайдеров: отдельные ключи и каталоги,
наследуемые настройки модели, `x-project`, построение URI модели и общий предел одновременных
запросов. В `.env` подготовлены пустые поля для пяти ключей/каталогов; остальные секреты сохранены.
Для пяти независимых облаков задан `YANDEX_TOTAL_PARALLEL=5`, по одному запросу на ключ.
Пример для одного облака консервативно ограничен двумя общими запросами.

Новый тест синхронизирует пять одновременных вызовов, подтверждает использование всех пяти
аккаунтов, сохранение порядка и отсутствие потери строк. Это модульная проверка с подменённым
HTTP/LLM, **не реальный замер Yandex**: его ключи ещё не заполнены. Инструкция — `docs/yandex.md`.
