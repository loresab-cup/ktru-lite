# Оптимизация DeepSeek через Яндекс, 28 октября 2026

Продолжение: [гибридный режим на полной спецификации из 1000 строк](structured-optimization-2026-10-28.md).
Измерения ниже относятся к этапу, когда все строки ещё отправлялись в DeepSeek.

Один `YANDEX2_API_KEY`, модель `deepseek-v4.1-flash/latest`, reasoning `none`.
Сравнение через полный HTTP pipeline на изолированных SQLite backend с одним и тем же
каталогом 81 509 кодов и локальной bge-m3. Основные пользовательские задания не менялись.

Выборка зафиксирована: 100 строк с шагом 10 из организаторской спецификации на 1000 товаров.
Все 100 описаний различны. Эталон — исходный `Спецификация_1000_reference.jsonl`.
Второе мнение по спорным кодам включено в обоих режимах. Поиск, веса и пороги не менялись.

Цена рассчитана по тарифам на скриншоте пользователя: 0,30 ₽ за 1000 входных и 0,50 ₽ за
1000 выходных токенов. Источник количества токенов — `usage` каждого реального ответа API,
зафиксированный диагностическим hook без записи ключей. Итог биллинга, скидки и возможные
изменения тарифов могут отличаться. Скорость улучшилась примерно в 3 раза, расчётная
стоимость снизилась на 35%. Выигрыш времени включает и компактный формат, и параллельность;
это не отдельный замер каждого фактора. Общий Ollama-кэш мог помогать последующим прогонам.

Компактный JSON использует поля `n,b,m,c,s,u`; `c` — массив троек имени, значения и единицы.
Пустые поля пропускаются. Родовое название `s` не повторяет характеристики; поисковый текст
собирается локально из проверенных значений. Если короткое родовое название — подмножество
полного имени товара, берётся полное имя, чтобы не терять назначение и уточнения. Явная
единица закупки из исходной строки сохраняется. Публичный формат атрибутов не менялся.

Первый компактный эксперимент дал 95/100 кодов из-за потери уточняющих слов названия.
Он не применён к основному backend. После общего исправления сборки поискового текста
новый реальный прогон вернул 96/100 без потери ранее правильных строк.

Проверки: 148 backend-тестов прошли, 10 пропущены (отсутствующие внешние фикстуры и каталог
для отдельной проверки). Ruff check и format check прошли. Фронтенд этим изменением не
затрагивался; его lint/build ранее прошли. Старый внешний черновой эталон отсутствует,
поэтому проверка на нём не заявляется. Новый режим на полном наборе 1000 строк ещё не
замерен; не обещаем выполнение за 5 минут на неизвестном оборудовании. Этот эталон не
подтверждает полноту распознавания брендов и моделей на разнообразных реальных товарах.

Локальные артефакты (не входят в Git): `audit-results/deepseek-optimization/` — исходные и
финальные items, usage-логи, сравнение кодов. Режим отката: `LLM_COMPACT=0`,
`YANDEX2_PARALLEL=2`, `YANDEX_TOTAL_PARALLEL=2`; затем пересоздать backend после завершения
активных заданий.
